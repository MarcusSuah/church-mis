# React Frontend (Control C18, plus client side of C5 and C10)

This skill owns **C18 XSS prevention** and the browser-side rules for **C5 token storage** and
**C10 secret exposure**. Server-side counterparts are in `laravel-api-security`.

Also activate:

- `inertia-react-development` for Inertia v3 APIs (forms, deferred props, prefetching, `useHttp`).
- `wayfinder-development` for every URL the frontend calls.
- `tailwindcss-development` for styling.

## 2. Project structure and conventions

| Path                                          | Purpose                                                                                                                                              |
| --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `resources/js/pages/<module>/index.tsx`       | Inertia pages. Folder names are lowercase-kebab, except the existing `Admin/*`.                                                                      |
| `resources/js/components/ui/*`                | shadcn primitives. Excluded from lint and format. Change them rarely and deliberately.                                                               |
| `resources/js/components/ssbcms/*`            | App-wide building blocks: `Pagination`, `MemberPicker`, `ImageUploadField`, `ConfirmModal`, `LoadingSkeleton`, `StatusBadge`. Reuse before creating. |
| `resources/js/hooks/*`                        | `use-permissions`, `use-list-filters`, `use-flash-toast`, `use-member-options-search`, and others.                                                   |
| `resources/js/types/*`                        | Shared types. `SharedData` in `types/index.ts` and `User` in `types/auth.ts` mirror `HandleInertiaRequests::share()`.                                |
| `resources/js/actions`, `routes`, `wayfinder` | Generated by Wayfinder. Git-ignored. Never edit by hand.                                                                                             |

Rules:

- Use `cn()` from `@/lib/utils` to merge classes. Use shadcn primitives (`Button`, `Dialog`, `Table`, `Field`, `Select`) before raw elements.
- Type every page's props. Update `SharedData` when the server's shared props change.
- The React Compiler memoizes automatically. Do not add `useMemo` or `useCallback` without a measured reason.
- Lists use the server's pagination meta from `ListQuery::meta()` with the existing `Pagination` component, and `use-list-filters` for query-string state.
- Deferred props show a `Skeleton` or `LoadingSkeleton` placeholder while loading.
- Support dark mode with Tailwind `dark:` variants, as existing pages do.
- Accessibility: every input has a `Label`, icon-only buttons have `aria-label`, and dialogs use the shadcn `Dialog` or `AlertDialog`.

Never commit compiled output (`dist/` folders, `.js` copies of pages) under `resources/js`. Only `public/build` holds build output.

## 3. Talking to the server

Preferred order:

1. **Inertia navigation and forms**: `<Form>`, `useForm`, `router.visit/post/patch/delete`, with Wayfinder for URLs.
   Inertia sends the CSRF token and handles 419 and validation errors.
2. **Inertia `useHttp`** for JSON endpoints that should not navigate (lookups, uploads).
3. **`fetch`** only where an existing component already uses it. Copy the `ImageUploadField` pattern:
   Wayfinder URL, `credentials: 'same-origin'`, and the `XSRF-TOKEN` cookie sent as `X-XSRF-TOKEN`.

```tsx
import { Form } from '@inertiajs/react';
import { store } from '@/actions/App/Http/Controllers/Finance/TitheController';
import InputError from '@/components/input-error';

export function TitheForm() {
    return (
        <Form {...store.form()} resetOnSuccess>
            {({ errors, processing }) => (
                <>
                    <input name="amount" inputMode="decimal" />
                    <InputError message={errors.amount} />
                    <button type="submit" disabled={processing}>
                        Save
                    </button>
                </>
            )}
        </Form>
    );
}
```

Never hardcode URLs. Use Wayfinder route helpers.

## 4. Axios

Axios is **not installed**, and Inertia v3 no longer ships it. Do not import it and do not install it unasked.
If the user approves adding it (for example for a separate SPA or mobile web client), configure one shared
instance and use it everywhere:

```ts
// resources/js/lib/http.ts
import axios from 'axios';

export const http = axios.create({
    baseURL: '/',
    withCredentials: true,
    withXSRFToken: true,
    headers: {
        Accept: 'application/json',
        'X-Requested-With': 'XMLHttpRequest',
    },
    timeout: 15000,
});
```

- Never set an `Authorization: Bearer` header from browser storage. See Section 6.
- Never point `baseURL` at a third-party origin. Third-party calls happen on the server.
- Handle `401` and `419` by reloading through Inertia, `403` with a toast, and `422` by mapping `errors` into the form.

## 5. C18: XSS prevention

React escapes text in JSX. XSS enters through the escape hatches below. Handle each one.

### 5.1 `dangerouslySetInnerHTML`

- The single allowed use is the 2FA QR code in `components/two-factor-setup-modal.tsx`. That SVG is generated
  server-side by Fortify from a secret the server created, with no user text in it.
- Any other use needs a sanitizer. None is installed, so adding DOMPurify requires approval. Until then, render
  user content as text.
- Never build HTML strings from props or API data.

Check the codebase:

```bash
grep -rn "dangerouslySetInnerHTML\|innerHTML\|outerHTML\|insertAdjacentHTML\|document.write\|new Function\|eval(" resources/js --include=*.ts --include=*.tsx | grep -v "/dist/"
```

The expected result is only the QR code line.

### 5.2 URLs in `href`, `src` and `window.location`

User-controlled URLs (document links, website hero slides, sermon media, logos, avatars) can carry `javascript:` or `data:` payloads.

```ts
// resources/js/lib/safe-url.ts
const ALLOWED_PROTOCOLS = new Set(['http:', 'https:', 'mailto:', 'tel:']);

export function safeUrl(value: string | null | undefined): string | undefined {
    if (!value) {
        return undefined;
    }

    try {
        const url = new URL(value, window.location.origin);

        return ALLOWED_PROTOCOLS.has(url.protocol) ? url.toString() : undefined;
    } catch {
        return undefined;
    }
}
```

- Wrap every user-supplied `href` or `src` with `safeUrl()` from `@/lib/safe-url` (it already exists). The server must also validate with `url:http,https`
  (see `laravel-api-security`). Both layers are required.
- Links that open a new tab use `target="_blank" rel="noopener noreferrer"`.
- Never navigate to a URL taken from the query string without checking it is same-origin (open-redirect).

### 5.3 Rich text and long text

- Pastoral notes, prayer requests, announcements and website copy render as text. Preserve line breaks with
  `whitespace-pre-line`, not with HTML.
- `ReadMore` and `StatusBadge` take strings, not markup.

### 5.4 Server-rendered output

- Blade and DomPDF certificate templates use `{{ }}`. `{!! !!}` is allowed only for content generated by code with no user input.
- JSON embedded in Blade uses `@json` or `Js::from()`.
- A Content-Security-Policy header is a server-side defense-in-depth layer. Propose it to the user; it needs testing with Vite's dev server and Inertia.

## 6. C5 (client): token and credential storage

- The app authenticates with the Laravel session cookie (HttpOnly, set by the server). JavaScript never needs to read a credential.
- **Never** store API tokens, passwords, 2FA codes, recovery codes, reset tokens or personal data in `localStorage`,
  `sessionStorage`, IndexedDB, non-HttpOnly cookies, or URL query strings.
- Allowed browser storage is UI preference only. Current uses: `appearance` in `use-appearance.tsx`, and the grid or list
  view mode in `pages/member-directory/index.tsx`.
- Recovery codes and a newly created API token are shown once, held only in component state, and cleared when the dialog closes.
- On logout, let Inertia perform a full visit so in-memory state is dropped.

```bash
grep -rn "localStorage\|sessionStorage\|indexedDB" resources/js --include=*.ts --include=*.tsx | grep -v "/dist/"
```

## 7. C10 (client): no secrets in the bundle

- Every `VITE_*` variable is compiled into public JavaScript. Only `VITE_APP_NAME` exists today. Never add a secret with the `VITE_` prefix.
- Map keys, analytics ids and similar values are public by design. Restrict them by domain at the provider.
- Anything that needs a secret runs on the server, and the page receives only the result.

```bash
grep -rn "import.meta.env" resources/js --include=*.ts --include=*.tsx | grep -v "/dist/"
```

## 8. Permissions in the UI

- `usePermissions()` (`can`, `hasRole`, `isMemberOnly`) only hides navigation and buttons. The server enforces the rule.
- Never send data to the page that the user cannot see and then hide it. The controller must omit it.
- Handle a 403 flash toast gracefully. `use-flash-toast` already shows server toasts.

## 9. Forms and validation

- Client-side checks (`required`, `maxLength`, `inputMode`) are UX only. Server validation is the control.
- Show server errors with `InputError` next to the field.
- Disable submit while `processing` to prevent double posts of financial records.
- Monetary input uses `inputMode="decimal"` and sends strings. The server parses them.

## 11. Review checklist

- [ ] No new `dangerouslySetInnerHTML`, `innerHTML` or `eval`; user text renders as text.
- [ ] User-supplied URLs pass through `safeUrl()`; external links use `rel="noopener noreferrer"`.
- [ ] No credentials or personal data in browser storage or URLs.
- [ ] No secrets in `VITE_*` variables or hardcoded in source.
- [ ] Server calls use Inertia, `useHttp` or the documented `fetch` pattern, with Wayfinder URLs.
- [ ] Axios not imported unless the user approved installing it.
- [ ] Permission checks in the UI have a matching server-side check.
- [ ] Page props are typed; `SharedData` matches the server.
- [ ] shadcn primitives and existing `ssbcms` components were reused.
- [ ] `types:check`, `check` and `build` were run and their results reported.

## 12. Acceptance criteria

1. A stored value such as `<img src=x onerror=alert(1)>` or `javascript:alert(1)` displays as inert text or is dropped, never executed.
2. Browser storage contains only UI preferences after login, use and logout.
3. The production bundle contains no secret values (search `public/build` for known secret names after `npm run build`).
4. Every UI-hidden action is also rejected by the server for a user without the permission.
5. `npm run types:check` and `npm run check` pass, and the outputs were reported.
